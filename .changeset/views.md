Add `createTreecrdtView` (`@treecrdt/interface/views`) for the SQLite-backed engines: it lists the members of each key of a payload index as a group, at default keys built from each member's rank and read from its payload, and stores nothing for a member until someone places it. `place`, `createFolder` and `removeFolder` write only what a drop needs: the group's node under a view root if it is missing, the reference node of the item placed (per member, or per member's parent), and the reference of a member an item goes under. A group's top level merges its references and folders, by order key, with its members that have no reference, by default key, so a drop between two members takes a key between theirs; below it, references and folders nest as ordinary siblings. The view root, group nodes and the references written for nesting are create-only inserts at keys every device derives alike, so none moves a reference someone placed. **The first placement adds a view root among the root's children on every replica, so everything that reads the root's children, walks the tree or listens to `onMaterialized` (lists, exports, sibling placement) must skip nodes whose ids start with `VIEW_NODE_PREFIX`, and a writer whose capability covers only a subtree cannot order a group.**
